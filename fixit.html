Fix It Lab

The shop's photos are broken and it's your job to find out why. This lab teaches file paths: how a page tells the browser where an image or stylesheet lives, and why one wrong letter breaks it. Go in order: learn it, watch it, get quizzed, then fix real broken code.

A path is directions to a file

The browser starts where the page is

When a page says <img src="img/home.png">, the browser starts in the same folder as that page and follows the directions one piece at a time: open the img folder, then grab the file called home.png.

site/
├── index.html      ← the page starts here
├── styles.css
└── img/
    └── home.png    ← "img/home.png" ends here

The three pieces you'll use

  • home.png means the file is in the same folder as the page.
  • img/home.png means go into the img folder first.
  • ../img/home.png means go up one folder first. You need this when the page itself is inside a folder.

It has to match letter for letter

On GitHub Pages, Photo.JPG and photo.jpg are two different files. Capital letters, the folder name and the extension (.png, .jpg) all have to match exactly. Macs and Windows PCs usually ignore capitals, so a path can work on your laptop and still break on the live site.

src or href?

  • <img src="…">: an image uses src.
  • <a href="…">: a link uses href.
  • <link rel="stylesheet" href="…">: the stylesheet also uses href.

The rules for writing the path are the same for all three.

Clue: the alt text shows up

When an image can't be found, the browser shows a broken-image icon and your alt text instead. If you see your alt text, the tag worked but the path is wrong.
